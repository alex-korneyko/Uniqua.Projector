| S-01 | The per-address cap key is `source + ␟ + normalised email`, and nothing limits the email's length. openapi's `maxLength: 256` is not enforced, and the only limit is Kestrel's 30 MB body limit. The per-address slot is reserved before the per-source check. When the per-source ceiling refuses, `Release` leaves an empty list in `_entries` until the next prune, which runs once per window. So a source already refused at 100 can send cheap 429 attempts, with no hashing, each with a new huge address. Each leaves a key, up to 100,000. That can fill gigabytes from one source, so the §6.1 memory bound is untrue. Guessed addresses are also kept in plain text, while `InMemoryUnknownAddressAttempts` hashes the same value. | `Api/Accounts/SignInRateLimit.cs:108-121,143-144`; `Api/Accounts/SlidingWindowLimiter.cs:108-119`; `AccountEndpoints.cs:175-184`; `spec.md:223`; `openapi.yaml:524,531` | AC-12, AC-05b | Fix now:<br>• key on the hex SHA-256 of the normalised email;<br>• reserve the per-source slot before the per-address one, so an attempt the per-source ceiling refuses creates no per-address entry;<br>• drop a list in `Release` once it is empty;<br>• enforce email ≤ 256 and password ≤ 128 before `Reserve`, with the same uniform refusal;<br>• test that a flood of new addresses from a capped source leaves the per-address tracked count unchanged. |
| S-02 | §6.1 says the ceiling counts "100,000 distinct sources", but for the per-address limiter it counts (source, address) pairs, shared by every source. About 1,000 sources with 100 addresses each fill it within one window. After that the per-address cap is silently skipped for every new pair, so a new source can make up to 100 guesses at one account instead of 20. `SignInRateLimit.TrackedSourceCount` reports only the per-source count, and no test covers the per-address ceiling. | `spec.md:223`; `SlidingWindowLimiter.cs:30,55-72`; `SignInRateLimit.cs:76-77,87`; `RequestSourceTests.cs:62` | AC-12 | Fix now:<br>• reword §6.1 and the ADR 0010 amendment: the ceiling counts pairs, and past it the fallback is the per-source figure of 100;<br>• expose the per-address tracked count and test that limiter at its ceiling. |

Continuous refused attempts therefore don't prevent the reset. | `spec.md:186`; `AccountEndpoints.cs:109-117`; `Domain/Accounts/GuessingDelay.cs:52-67`; `IdentityAccountStore.cs:194-201` | AC-12 | Fix now (docs): reword AC-12, the §6 row and `test-plan.md:66` to "…after 15 minutes in which no failed attempt reached verification".
