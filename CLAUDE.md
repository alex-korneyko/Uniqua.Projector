# Uniqua.Projector — working rules

A Kanban board: accounts, boards, columns, cards, checklist items, invitations, and live updates
pushed to everyone viewing a board. The decisions below are the foundation fixed in
`docs/architecture-map.md` and `docs/adr/0001`–`0005`. This file restates them as rules; the map is
the source, so if the two ever disagree, the map wins and this file is wrong.

## Commands

| What | Command |
|---|---|
| Build server | `dotnet build Uniqua.Projector.slnx` |
| Test | `dotnet test Uniqua.Projector.slnx` |
| Format check | `dotnet format --verify-no-changes` |
| Build client | `npm --prefix src/Uniqua.Projector.Web run build` |
| Lint client | `npm --prefix src/Uniqua.Projector.Web run lint` |
| Add a migration | `dotnet ef migrations add <Name> --project src/Uniqua.Projector.Infrastructure --startup-project src/Uniqua.Projector.Api --output-dir Migrations` |

The solution is `.slnx` (the .NET 10 XML solution format), not `.sln`.

## Project reference direction

`Api → Application → Domain` and `Infrastructure → Application → Domain`. Domain references
nothing. Api references Infrastructure only to register implementations at startup. This direction
is load-bearing: it is what keeps the four-project split from being ceremony, and a reference that
runs the other way is a defect, not a shortcut.

## Domain rules live in Domain

An invariant — "a card cannot move to a column of another board", "a board must keep at least one
column" — is enforced by the entity itself, never by a use case and never by an endpoint. A use
case orchestrates; it does not decide what is legal. This is the single rule this architecture is
most likely to lose under time pressure, and losing it is what turns the layering into overhead.

## Errors are ProblemDetails, from one handler

Every failure response is an RFC 9457 `application/problem+json` document produced by the handler
in `src/Uniqua.Projector.Api/ProblemDetailsSetup.cs`. An endpoint never builds an error shape of
its own and never returns a bare status code with an ad-hoc body.

## Ids are GUID version 7, generated by the application

New identifiers come from `Uniqua.Projector.Domain.Ids.New()`, which returns a GUID v7. They are
time-ordered, so inserts stay at the end of the clustered index instead of fragmenting it, and they
do not leak how many rows exist the way a sequential integer would. The database never generates an
id.

## Persistence is EF Core, behind ports, in Infrastructure

`AppDbContext` lives in `src/Uniqua.Projector.Infrastructure/` and is reachable from nowhere else —
Domain does not know it exists and Api only registers it. Application declares the repository ports
it needs; Infrastructure implements them.

Schema changes are EF Core migrations generated from the model, one per change, reviewed as SQL
before they are applied. They run on startup in development and as an explicit step in deployment.

## Layer wiring

Each layer exposes one `AddXxx(IServiceCollection)` extension, called from `Program.cs`. That file
names no type from inside a layer. A new dependency is registered in its own layer's
`DependencyInjection.cs`, not in `Program.cs`.

## Test floor

The floor is narrow and real, and it is a lower bound rather than a target:

- Integration tests that boot the application through `WebApplicationFactory` against a SQL Server
  container (`tests/Uniqua.Projector.Api.IntegrationTests/ApiFactory.cs`), covering registration
  and sign-in, a non-member being refused a board over both HTTP and the push channel, and a card
  move.
- Unit tests on Domain invariants only (`tests/Uniqua.Projector.Domain.Tests/`).

The container start is slow, locally and in CI. That cost is accepted: an in-memory provider would
not exercise the store this application ships against. If the schedule slips, it is absorbed by
scope, not by dropping below this floor.

## Styling: Tailwind, once

Tailwind utility classes are the only styling mechanism in this repository. shadcn/ui components
are vendored as source under `src/Uniqua.Projector.Web/src/components/ui/` and edited in place, not
installed as a dependency. A second styling mechanism — CSS modules, styled-components, inline
style objects — is a review finding, not a preference.

TanStack Query owns all server state. A push event invalidates or patches the cached board rather
than maintaining a second copy of it. No global client-state library is introduced until something
actually needs one.

## One origin

The API serves the built client from `wwwroot`, and the Vite dev server proxies API calls to it.
The session cookie is httpOnly and same-origin, so the client and the API cannot be split across
two hosts. Any hosting proposal that separates them breaks authentication.

## Licensing: permissive only

Every dependency must be MIT, Apache-2.0, or BSD-style. Do not introduce a GPL, LGPL, AGPL, or
otherwise copyleft component into this repository. If a copyleft library is the obvious technical
fit, say so explicitly and propose a permissive or commercial alternative instead of adding it.
Package versions are managed centrally in `Directory.Packages.props`.
